## 2. Implementovaná architektúra

Rovnaký defense-in-depth vzor ako K13.3.1–K13.3.5 (žiadny service-role):

1. **Stránka** (`page.tsx`, server component):
   - `requirePermission(PERMISSIONS.REPORTS_VIEW)` ako **prvý** krok — pred
     akýmkoľvek čítaním dát; existujúce správanie guardu zachované.
   - AND gating z katalógu (`isReportAccessible`): `reports.view` A `finance.view`;
     bez `finance.view` sa dáta vôbec nečítajú (karta „Report nie je dostupný").
   - Voliteľný filter mesiaca z URL (`?month=YYYY-MM`), neplatný tvar sa ignoruje.
2. **Služba** (`finance-ledger.service.ts`):
   - `authorizeFinanceLedger()`: `getAuthContext()` → AND filter chýbajúcich
     oprávnení → potvrdenie **každého** oprávnenia cez server RPC
     `hasPermissionServer` (priame volanie služby neobíde oprávnenia).
   - Čítanie cez štandardný SSR `createClient()` (RLS; **0** výskytov
     `service_role` — overené staticky).
   - Jeden SELECT `finance_transactions` (9 stĺpcov — žiadne ceny/náklady),
     `.eq("status","POSTED")`, zoradenie zostupne podľa dátumu, strop
     **500** riadkov (`LEDGER_MAX_ROWS`, +1 na detekciu prekročenia) +
     voliteľný rozsah dátumu pre filter mesiaca; jeden SELECT
     `finance_categories` (id, name) na názvy kategórií. Obe tabuľky má pod
     RLS `finance.view`.
3. **Agregácia** (`reports.core.ts`, čistá `buildFinanceLedger()`): filtruje
   POSTED, kontroluje dátum/typ, počíta signed sumy a totály, radí vzostupne
   podľa dátumu (potom `id`). Unit-testovaná bez IO.
4. **UI**: `Card`/`Badge`/`Button` (existujúci dizajnový systém); tabuľka
   Dátum / Typ (badge) / Kategória / Popis+doklad+kontrahent / podepsaná suma
   (červená záporná, zelená kladná); päta s príjmami, výdavkami, počtom
   prevodov a netto; spätný odkaz na `/reports`.

## 3. Finančné invarianty (unit-testované)

- Do denníka idú **výhradne** riadky `status='POSTED'` — dvakrát:
  `.eq("status","POSTED")` v dotaze **a** filter v `buildFinanceLedger()`.
- `TRANSFER_IN`/`TRANSFER_OUT` sú **cash-flow neutrálne** — v položkách majú
   podepsanú sumu (±), ale nikdy nevstupujú do `incomeMinor`/`expenseMinor`
  (len `transferCount`) — zhodné s K13.3.5 a K13.3.0 §7.2.
- `signedMinor`: INCOME/TRANSFER_IN = +, EXPENSE/TRANSFER_OUT = −.
- Neplatný `transaction_date` alebo neznámy `type` → riadok preskočený.
- Sumy v minor units; EUR len v prezentačnej vrstve (`eur()`).
- Prázdny výsledok: `entries=[]`, totály nulové, UI bez chyby.
