### 3.4 🔴 KRITICKÝ NÁLEZ — konflikt poradia dvoch `20261022` migrácií

Oba súbory obsahujú `CREATE OR REPLACE FUNCTION public.finance_guard_transactions()`
a majú **opačnú semantiku**:

* **`..._finance_transactions_guard_fix.sql` (K13.2.4)** — pridáva podmienku
  `v_uid IS NOT NULL AND` ku všetkým 4 kontrolám `finance.edit`
  (riadky 85, 117, 141, 154). Dôsledok — citát z vlastnej dokumentácie
  `K13.2.5_COMPLETION_REPORT.md`:
  > *„any request where `auth.uid() IS NULL` **bypassed the posting authorization
  > entirely**; NULL identity became implicitly trustworthy."*

* **`..._finance_transaction_guard_fix.sql` (K13.2.5)** — tento stav **opravuje**:
  podmienku `v_uid IS NOT NULL` z K13.2.4 explicitne **odstraňuje** (vlastný
  komentár, riadok 20) a namiesto nej vyžaduje session GUC
  `app.finance_pti_enabled = 'on'`, ktorý vie nastaviť len
  `public.finance_pti_enable()` — tá je `GRANT EXECUTE ... TO service_role`
  a `REVOKE ... FROM public, anon` (riadky 70–71).

**Závislosť:** K13.2.5 má zmysel **až po** K13.2.4.

**Poradie podľa mena súboru (lexikograficky):**

```
20261022_finance_transaction_guard_fix.sql   → po spoločnej predpone „…transaction"
                                              ďalej '_' (0x5F)
20261022_finance_transactions_guard_fix.sql  → po spoločnej predpone „…transaction"
                                              ďalej 's' (0x73)
0x5F < 0x73  ⇒  K13.2.5 (oprava) sa zaradí PRVÁ, K13.2.4 (obchádzačka) DRUHÁ
```

**Dôsledok pri čistej inštalácii (`supabase db push` na novej DB):**
posledne aplikovanou definíciou bude variant **K13.2.4**, t. j. variant, ktorý
**obchádza kontrolu oprávnenia pri NULL identite** — hardening K13.2.5 by bol
ticho prepísaný.

> **Poznámka o istote:** Supabase CLI radí migrácie podľa časovej predpony.
> Pri **rovnakej** predpone je poradie aspoň lexikografické podľa mena súboru,
> v lepšom prípade nedeterministické (Go `sort.Slice` nie je stabilný). V oboch
> prípadoch je výsledné poradie **neisté a nezdokumentované**. Presný dopad na
> vzdialenú DB možno potvrdiť len runtime testom → **BLOCKED**, ale riziko je
> staticky preukázané jednoznačne.

**Priorita: P0 / CRITICAL (security)**
