## 5. Bezpečnostný model a matica oprávnení

### 5.1 Princíp: dvojitý gate (UI/server + RLS)
1. **UI/server gate:** `requirePermission(reports.view)` vstup do modulu; export `requirePermission(reports.export)`.
2. **Zdrojový gate:** každý report **dodatočne** vyžaduje čítacie oprávnenie zdrojového modulu (`members.view`, `training.view`, …, `finance.view`). RLS je **posledná** obranná línia.

**Pravidlo kombinácie (bez nových permission kľúčov):**
- Zobraziť report → `reports.view` **AND** perm zdroja.
- Exportovať report → `reports.export` **AND** perm zdroja; pre financie (R8–R10) ešte **`finance.export`**.
- Kombinovaný report (R4 = trainings+competitions) → server filtruje každú čas podľa perm zdroja; chýbajúci perm zdroj **neodhalí**.

### 5.2 Matica roly × report (z role_permissions grants)

| Role | R1 members | R2 training | R3 compet | R4 kalendár | R5/R6 inv/veh | R7 incidents | R8–R10 finance |
|---|---|---|---|---|---|---|---|
| **ADMIN** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ (view+export) |
| **VEDENIE** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ (view) | ✅ (view+export) |
| **VELITEL** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ (view) | ❌ (žiadne finance.*) |
| **POKLADNIK** | ✅ | ❌ | ❌ | ✅ (view) | ✅ (view) | ❌ | ✅ (view+export) |

## 7. Finančné pravidlá a riziká

### 7.1 Stavy transakcií
| Stav | Význam | Do finančných reportov? |
|---|---|---|
| `DRAFT` | rozpracované, nezaúčtované | **NIE** |
| `POSTED` | zaúčtované, započítané do salda | **ÁNO** (jediný zdroj pravdy) |
| `VOID` | stornované (`void_reason` povinný) | **NIE** |

Pohľad `finance_account_balances` sčítava **len POSTED** — reporty držia rovnakú invariantu.

### 7.2 Príjmy, výdavky, saldo, prevody
- Príjem = `SUM(amount_minor) WHERE type='INCOME' AND status='POSTED'`.
- Výdaj = `SUM(amount_minor) WHERE type='EXPENSE' AND status='POSTED'`.
- Saldo účtu = `opening_balance_minor + Σ(signed POSTED)` — nikdy uložené, vždy z pohľadu.
- **Prevod** = pár (`TRANSFER_OUT` na zdroji + `TRANSFER_IN` na cieli) s `transfer_group_id`,
  identická kladná suma. Hotovosť organizácie sa prevodom **nemení**; guard
  `finance_guard_transfer_group` (DEFERRABLE, COMMIT) zaručí presne jeden OUT+IN,
  rovnaká suma, zhodný status. V cash-flow (R9) prevody neuvádzať; per-účet (R8/R10) áno.

### 7.3 Riziká
| # | Riziko | Závažnosť | Mitigácia |
|---|---|---|---|
| K1 | Report zahrnie DRAFT/VOID do finančného súčtu | HIGH | filtrovať `status='POSTED'`; test T8 |
| K2 | Export financíí bez `finance.export` | HIGH | dodatočný gate + audit (T3/T9) |
| K3 | Nesúlad `vehicle.view` vs RLS `inventory.view` | MED | riadiť RLS; zdokumentovať |
| K4 | NULL `auth.uid()` obíde autorizáciu | HIGH | `requirePermission` + RLS odmietnu; T6 |
| K5 | Neobmedzený SELECT pri exporte | MED | strop riadkov + `.range()`; T10 |
| K6 | NULL agregované hodnoty (`result_*`, attendance) | LOW | `COALESCE`/`FILTER` |
| K7 | Chýba tabuľka kalendára/porúch | MED | R4=UNION trainings+competitions; poruchy=maintenance/incidents |
| K8 | Zaujaté znamienko prevodov v cash-flow | MED | prevody vylúčiť z R9 |

## Zhrnutie

- `/reports` je **placeholder** (`reports.view` gate). Žiadne report komponenty/služby/exporty doteraz.
- DB má **jeden pohľad** (`finance_account_balances`, security_invoker) a **žiadnu**
  tabuľku kalendára ani porúch — kalendár = UNION(trainings,competitions).
- V1 = **10 read-only reportov**; bezpečnosť = **dvojitý gate** (`reports.view`/`reports.export`
  AND perm zdroja; financie ešte `finance.export`).
- Financie: počítať **len POSTED**; saldo odvodené; prevody sa v cash-flow rušia.
- Kľúčové riziká: zahrnutie DRAFT/VOID, export bez `finance.export`, NULL identity,
  nesúlad `vehicle.view`↔`inventory.view`.
- **Runtime testy BLOCKED** (žiadna dev DB); žiadny runtime „PASS" nie skutočný.

K13.3.0 je **hotový** (iba dokumentácia). **Nezahájené** K13.3.1 ani žiadna
implementácia — čakám na ďalší pokyn.

- Každá funkcia: `getAuthContext()` → kontrola perm zdroja (resp. `requireAnyPermission`)
  → `createClient()` (RLS) → SELECT so stropom. **Žiadne zápisy, žiadny service-role.**
- Financie: obmedziť `status='POSTED'`; export skontroluje `finance.export` + audit.

### 6.2 UI (návrh)
- `/reports` — katalóg (karty), každý s gatom podľa perm zdroja.
- `/reports/[id]` — filter panel + výsledková tablica + „Export" (len pri
  `reports.export`; financie ešte aj `finance.export`). Znovupoužiť `@/components/ui/*`.

### 6.3 Exportná stratégia (návrh)
- **CSV** (primárny): server action `generateReportCsv(reportId, filters)` →

- **PDF**: pre tlačové reporty (R1/R3/R7/R8) voliteľne — knižnica **nie je** v
  `package.json` (overiť pred použitím; nepridávať bez rozhodnutia).
