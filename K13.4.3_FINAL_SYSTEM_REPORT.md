**4-vrstvový bezpečnostný model** (overený auditom K13.3.7, platí pre celý projekt):
`requirePermission` guard → katalógové AND (`reports.view` + zdrojové oprávnenie)
→ vlastná autorizácia služby + RPC `has_permission` → RLS databázy. Žiadny
`service_role` mimo serverového Deno kontextu Edge Function; žiadne exporty
v reportoch; financie výhradne POSTED.

## 5. Známe blokády (kumulatívne)

1. **Autorizovaná DEV databáza** — blokuje: E2E scenáre (§3), runtime overenie

## 6. Návod na ostré nasadenie (keď je LIVE pripravené)

1. `supabase db push` (overené migrácie) → seed účty ADMIN/POKLADNIK → priradiť roly.
2. Overiť RLS maticu T1–T10 (K13.3.0 §5.4) na DEV DB; potom E2E `e2e/` (§3).
3. VAPID pár → env `NEXT_PUBLIC_VAPID_PUBLIC_KEY` + Edge secrets
   (`VAPID_PRIVATE_KEY`, `VAPID_PUBLIC_KEY`, `VAPID_SUBJECT`, voliteľne
   `PUSH_CRON_SECRET`); `supabase functions deploy send-push`.
4. `next build` v CI (musí prejsť s 0 errors — predexistujúce diagnostiky
   vyriešiť pred produkciou) → deploy → PWA inštalácia na zariadení →
   offline test členov (`/members` z cache, `/finance` → 503).
5. CORS `*` v `send-push` zúžiť na produkčnú doménu; monitoring Edge Function logov.
