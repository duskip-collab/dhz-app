## 1. Zhrnutie

Druhý prevádzkový report **Prehľad inventáru a výzbroje** (`inventory-status`)
bol implementovaný a v katalógu zmenený z `planned` na `available`. Report
používa **duálnu serverovú autorizáciu** (`reports.view` AND `inventory.view`),
číta výhradne cez štandardný SSR Supabase klient (RLS) a **nečíta žiadne finančné
údaje** ani nepoužíva service-role.

## 3. Implementovaná architektúra

```
Katalóg (reports.core.ts)                    Serverová služba
  inventory-status:                           equipment-inventory.service.ts
  requiredPermissions=[reports.view,            ├─ getAuthContext()
    inventory.view], status="available",        ├─ AND kontrola oboch perm
  route="/reports/equipment-inventory"         ├─ hasPermissionServer() (2. línia)
        │                                      ├─ createClient() → RLS
        ▼                                      └─ summarizeEquipment()
   /reports (katalóg)                                │
     requirePermission(reports.view)                 ▼
     + link „Otvoriť report" ────────────► /reports/equipment-inventory
```

**Vrstvy obrany (defense-in-depth):**
1. **Stránka:** `requirePermission(REPORTS_VIEW)` na **prvom riadku** — pred
   akýmkoľvek načítaním dát. Neprihlásený → `/login`, bez `reports.view` → 403.
2. **Gating:** `isReportAccessible(definition, ctx.permissions)` — logika **AND**.
   Bez `inventory.view` sa dáta **nenačítajú** (`canView=false`).
3. **Služba:** `authorizeEquipmentInventory()` zopakuje AND kontrolu + potvrdí
   cez RPC `has_permission` pre obe oprávnenia. Priame volanie služby teda
   **neobíde** autorizáciu.
4. **RLS:** číta sa cez štandardný SSR `createClient()` (anon kľúč + cookies).
   **Žiadny service-role klient.** RLS na `equipment_items` je posledná línia.

## 4. Pilotný report a zdrojové dáta

| Položka | Hodnota |
|---|---|
| Report id | `inventory-status` |
| Zdrojové tabuľky | `equipment_items`, `equipment_categories` (join `equipment_items_category_id_fkey`) |
| Čítané stĺpce | `id, name, status, location, category(name)` |
| **Nečítané (finančné)** | `purchase_price`, `purchase_date`, žiadne `amount/balance` |
| Permission kľúče | `reports.view` AND `inventory.view` (existujúce) |
| Stav | `planned` → **`available`** |

**Ukazovatele:**
- `summary.total` = počet položiek (1 riadok = 1 kus; skladové `quantity` v schéme neexistuje — overené v `database.types.ts`).
- `summary.byStatus` = počty podľa `status` (NULL → `UNKNOWN`).
- Tabuľka: Názov · Kategória · Stav · Množstvo (1/ks) · Lokácia.

**Správanie pri nulovom výsledku:** `summarizeEquipment([])` → `total: 0`,
`byStatus: {}` bez chyby; stránka zobrazí „Zatiaľ nie sú evidované žiadne položky
inventára." (overené unit testom).

## 7. Otvorené riziká a závislosti

1. **`vehicle.view` vs `inventory.view` (RLS)** — **nezmenené** (zakázané v tejto
   fáze). Zaznamenané ako otvorená závislosť; pilotný report ho nevyžaduje
   (oslovuje `inventory.view`, ktoré RLS `equipment_items` rešpektuje).
2. **Množstvo/kusy** — schéma nemá stĺpec `quantity`; tabuľka uvádza 1 riadok = 1 kus.
   Ak bude evidencia kusov potrebná, vyžaduje zmenu schémy (mimo rozsahu).
3. **Runtime testy** — **BLOCKED** bez DEV DB (viď S1–S8 sú statické).
4. **Katalóg** — používateľ s `inventory.view` uvidí v katalógu 2 dostupné
   reporty; člen bez `inventory.view` uvidí len `members-overview`.
