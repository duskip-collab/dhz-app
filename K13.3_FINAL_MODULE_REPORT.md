## 2. Bezpečnostná architektúra (4-vrstvový model, AND gating)

**Vrstva 1 — Server guard stránky:** každá `/reports/*` stránka začína
`await requirePermission(PERMISSIONS.REPORTS_VIEW)` (overené: `reports` L102,
`equipment-inventory` L85, `events-overview` L102, `finance-ledger` L135,
`finance-monthly-summary` L154, `vehicle-status` L99). Neprihlásený/neoprávnený
= existujúce správanie aplikácie (redirect/odmietnutie); žiadne dáta sa
nečítajú pred autorizáciou.

**Vrstva 2 — Katalógové AND gating:** `isReportAccessible()` =
`requiredPermissions.every(...)` (čistý AND v `reports.core.ts` L200–201).
`reports.view` samotné NEDOSTAČUJE — každý report vyžaduje aj oprávnenie
zdrojového modulu (`members.view`, `calendar.view`, `inventory.view`,
`vehicle.view`, `finance.view`).

**Vrstva 3 — Serverová služba (defense-in-depth):** každá z 6 služieb má
vlastnú `authorize*()` funkciu: `getAuthContext()` → AND filter chýbajúcich
oprávnení (`missing.length > 0` → 403; overené: 1 check v každej službe,
žiadne `.some()` OR) → potvrdenie **každého** oprávnenia cez server RPC
`hasPermissionServer`. Priame volanie akejkoľvek služby teda neobíde
autorizáciu.

**Vrstva 4 — RLS databázy:** všetko čítanie cez štandardný SSR
`createClient()`; RLS na `members`, `trainings`, `competitions`,
`equipment_*`, `vehicle_details`, `finance_transactions`,
`finance_categories` vynucuje zdrojové oprávnenie. **Žiadny `service_role` /
`createAdminClient` v module** (grep = 0 zhôd).

**Finančné invarianty:** výhradne `status='POSTED'` (DRAFT/VOID vylúčené —
dvakrát: `.eq()` v dotaze + čistá funkcia); prevody `TRANSFER_IN/OUT` sú
cash-flow neutrálne (len `transferCount`, nikdy v príjmoch/výdavkoch); sumy v
minor units; **žiadny CSV/XLSX/PDF export** (grep = 0 zhôd); `finance.export`
nie je súčasťou requiredPermissions žiadneho `available` reportu.

## 4. Známe závislosti a blokády

- **DEV databáza (BLOCKED):** všetky runtime testy (RLS, `has_permission` RPC,
  prázdne výsledky, UI na živej DB) čakajú na autorizované DEV prostredie.
  Žiadna migrácia ani produkčný zásah sa v K13.3 nevykonali. Overovacia matica
  z K13.3.0 §5.4 (T1–T10) zostáva neprebehaná — spustiť pri prvej dostupnej
  DEV DB.
- **`vehicle.view` vs `inventory.view` RLS nesúlad** (K13.3.0 §2.5, otvorená
  závislosť z K13.3.3): RLS SELECT na `vehicle_details` používa
  `inventory.view`; report `vehicle-status` to obchádza serverovým gatingom
  (`vehicle.view`), **oprava migrácie je mimo rozsahu K13.3** a zostáva
  zapísaná ako technický dlh.
- **`searchParams` v RSC** — použitý existujúci vzor stránok; prechod na Cache
  Components (budúci projekt O2) bude vyžadovať async úpravu.
- **Strop 500 riadkov** finančného denníka bez serverovej paginácie — pri
  väčšom objeme dát zaviesť `.range()` alebo export (`reports.export` +
  `finance.export` + audit — K13.4+).
- **Chýbajúce reporty (`planned`):** training-attendance, competitions-results,
  incidents, finance-accounts, finance-cashflow — pripravené dáta/RLS
  existujú, implementácia je ďalšia fáza.
